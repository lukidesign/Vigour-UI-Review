# 阶段 A：采集安全与认证边界加固

日期：2026-09-16。状态：源码修改与自动回归通过；尚未发布，真实工具栏采集闭环待人工验收。

本文记录阶段 A 完成时的状态；后续连接机制与测试增量见 [阶段 B 记录](STAGE-B-REVIEW.md)。

## 目标与边界

在接入 Native Messaging 前，先保证扩展不会因重复点击、切换页面或迟到响应而上传错误截图，并在失败后恢复目标页面。

本次只修改 `design-acceptance` 源码。未覆盖用户已安装的 v0.0.1，未改写用户历史数据库，未提交 Git、推送 GitHub 或上传商店。版本暂不递增，避免把阶段性源码当成已交付的 v0.0.2。

## 已实现

- 移除 `tabs` 权限和所有网站的静态 content script 注入；只在明确采集操作后注入。
- 采集入口只接受本扩展 popup 来源；模式严格校验，单任务互斥。
- 服务预检前固定目标 tab/window；注入后绑定 documentId，监听切换、导航、关闭，截图前后再次校验页面和视口。
- 本地服务预检失败不冻结或滚动页面；采集支持取消、单步超时与总时限。
- 准备失败、取消、异常均尝试清理。content script 幂等注册；独立 20 秒看门狗、页面隐藏及离开时恢复临时样式和两个方向的滚动。
- 提交阶段禁用取消；提交结果不确定时提示检查最近采集，避免误称数据未保存。
- 弹窗重新打开可获取运行状态；增加取消按钮、键盘焦点样式和无障碍状态播报。
- 本地 API 删除扩展来源通配符，严格校验完整来源；仍需 Token，写请求仍需 CSRF。
- 开发环境扩展 ID 白名单配置见 `INSTALL.md`。Native Messaging 自动配对尚未实现。

## 对抗式审查记录

在运行测试前审查了以下攻击及故障路径，并添加回归：

1. 服务预检期间用户切页：修正为预检前固定目标，不能在网络等待后重新选择活动页。
2. 截图期间切走再切回：同时使用事件中止与截图前后校验，不仅比较最终 tabId。
3. 准备阶段修改页面后抛错：先建立恢复责任，再发 prepare；页面端自身也负责回滚。
4. 取消后 Chrome API 迟到：中止任务并保留锁直到清理完成，迟到响应不能继续提交。
5. 重复注入和旧任务恢复消息：每个文档仅一个监听器，恢复消息按 sessionId 隔离。
6. 上传已到服务但响应超时：不承诺服务端回滚，不自动重试提交。
7. 任意扩展与网页来源：入口校验具体 popup；API 只允许明确来源，配置通配符会拒绝启动。

## 尚未验证与发布门槛

自动化测试版 Chrome 的工具栏弹窗接口因窗口非活动状态不能打开；此次不能宣称完整用户点击采集已通过。

发布前必须在普通 Chrome 验收以下内容：

- 从真正的工具栏弹窗发起视口/整页采集，确认 activeTab 授权、上传和最近采集正常。
- 采集时切走再切回、关闭目标页、导航、调整窗口尺寸、关闭并重开弹窗。
- 取消和强制结束 worker 后恢复页面；检查未提交错误页面图片。
- 断开本地服务、无效令牌、未授权扩展 ID，确认错误提示和恢复步骤有效。
- 上传结果不确定时能从最近采集确认状态，无自动重复提交。
- 固定/吸顶元素、懒加载及横向滚动页面的截图与 DOM 坐标一致性，仍需真实样例验证。
