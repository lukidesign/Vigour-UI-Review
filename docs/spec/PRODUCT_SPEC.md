# Vigour UI Review 产品 SPEC

- 文档状态：Development Ready
- 版本：0.0.1
- 日期：2026-08-28
- 首发平台：macOS + Chrome
- 产品形态：Chrome 插件 + 本地 Web 工作台 + 本地图像分析服务

## 1. Problem Statement（问题陈述）

设计验收依赖设计师、开发和 QA 人工对照设计稿与开发页面，存在四个根本问题：

1. 差异定位慢：需要反复切换图片并靠肉眼寻找位置、尺寸和颜色偏差。
2. 描述不准确：问题常被描述为“看起来不对”，无法直接转化为开发修改值。
3. 结果不稳定：不同验收人员、缩放比例、显示设备和时间点会产生不同结论。
4. 复验不可追踪：问题、修改建议、证据和多次复验结果缺少统一记录。

本产品需要把设计验收变成可重复、可量化、可追踪的本地工作流，同时保证核心检测不依赖云端 AI。

## 2. Product Goals（产品目标）

1. 使用设计图和开发页面自动发现视觉还原问题。
2. 用“向右偏了 12px”“宽了 8px”等大白话输出量化差异。
3. 同时提供开发图标注、平铺对比和透明度叠加三种证据视图。
4. 支持项目、页面和多次复验记录，展示问题变化和还原度变化。
5. 核心检测本地可用；语义对齐、业务逻辑推测和自然语言解释按需调用用户配置的 AI。
6. 不直接修改代码，但能生成可复制的 CSS 或代码补丁建议。

## 3. Target Users（目标用户）

### 3.1 设计师

- 关注视觉差异、标注证据、还原度和整改优先级。
- 希望减少与开发反复确认问题位置和目标值的沟通。

### 3.2 前端开发

- 关注 DOM、计算后 CSS、当前值、目标值和修改建议。
- 希望获得可以复制的 CSS/代码补丁，但由自己决定是否应用。

### 3.3 QA

- 关注验收步骤、运行证据、通过标准、未检查项和复验状态。

MVP 不建立角色账号或权限体系。同一用户可以切换设计、开发、QA 三种信息视图。

## 4. Proposed Solution（方案描述）

### 4.1 产品组成

1. Chrome 侧栏：采集当前可视区域或整页开发页面、选择设计来源、查看进度与问题摘要。
2. 本地 Web 工作台：管理项目与历史、执行三种对比、查看完整问题、生成建议和导出报告。
3. 本地服务：管理项目数据、调用图像引擎、连接 Figma、适配 AI 供应商并生成报告。
4. 本地图像引擎：负责截图拼接、自动对齐、OCR、视觉差异检测、元素匹配和结果量化。

### 4.2 MVP 用户流程

1. 用户创建项目和页面。
2. 用户上传 PNG/JPG 设计图，或粘贴带 Frame/Node 的 Figma 链接。
3. 插件读取当前页面的视口、DPR、URL、DOM、文字和计算后样式。
4. 用户选择“当前可视区域”或“整页截图”。
5. 工具冻结 CSS 动画，加载懒加载内容，并应用项目已有的忽略区域。
6. 工具自动计算缩放、位移、裁切和对齐置信度；用户可人工微调。
7. 当几何对齐置信度不足时，工具使用 Figma 节点、DOM、OCR 锚点和可选 AI 进行语义组件对齐。
8. 工具执行核心检测和实验检测，并把同一元素的多个差异合并为一个问题。
9. 用户在标注、平铺、叠加三种模式中检查证据，并按角色切换信息视图。
10. 用户可按需执行 AI 解释、业务逻辑推测或生成补丁。
11. 用户导出标注 PNG、Markdown 或 JSON，并在修改后创建新的复验批次。

## 5. Scope（功能范围）

### 5.1 项目与历史

- 数据层级固定为：项目 → 页面 → 验收批次。
- 同一页面支持多个设计版本和多个开发截图。
- 每个批次记录输入素材、对齐参数、容差配置、问题、评分、导出物和运行日志。
- 历史列表展示时间、分数、通过状态、问题数量和相对上一批次的变化。

### 5.2 设计稿输入

#### 本地图片

- 支持 PNG、JPG/JPEG。
- 读取并记录像素尺寸、色彩空间和文件哈希。
- 不接受无法解码或尺寸超过安全上限的文件；给出明确错误。

#### Figma

- MVP 使用用户本地保存的 Personal Access Token。
- 接受指向指定 Frame/Node 的 Figma 链接。
- 读取目标 Frame 图片、节点结构、文字、边界和样式信息。
- OAuth 使用统一授权接口预留，但不在 MVP 中上线。

### 5.3 开发页面采集

- 支持当前可视区域截图。
- 支持自动滚动、懒加载触发和截图拼接的整页采集。
- 采集页面 URL、标题、视口、DPR、滚动尺寸和采集时间。
- 经用户授权后读取 DOM、可见文字、元素边界和计算后样式。
- 自动暂停 CSS 动画和过渡；允许用户框选动态区域并保存为页面级忽略规则。
- 固定/吸顶元素在整页拼接时去重；无法稳定拼接时自动降级为分段截图并提示用户。

### 5.4 对齐

#### 一级：几何对齐

- 自动计算缩放、X/Y 位移和裁切区域。
- 支持边缘、特征点、结构线和图像相关性联合估计。
- 输出对齐置信度和证据。
- 用户可拖动、缩放和重置对齐结果；人工结果优先于自动结果。

#### 二级：语义组件对齐

- 使用 Figma 节点、DOM 元素、OCR 文字和视觉区域建立组件候选关系。
- 几何对齐置信度不足或长页面局部变形时启用。
- 可选 AI 只用于候选重排、组件语义判断和解释，不替代确定性的像素测量。

### 5.5 检测能力

#### 稳定能力

- 元素位置偏差。
- 元素宽度、高度和面积偏差。
- 前景色、背景色和主要填充色差异。
- 文字内容差异。
- 元素缺失或多余。

#### 实验能力

- 字体家族、字重、字号和行高。
- 内外间距与布局间隙。
- 圆角、边框宽度和边框颜色。
- 阴影参数。
- 图标形状、尺寸和对齐。

实验能力必须在 UI、JSON 和导出报告中明确标记，不得与稳定能力混为同等置信度。

### 5.6 特殊内容

- 跨域 iframe、Canvas、WebGL 和视频仅执行像素级检测。
- 这些区域标记为“结构不可验证”，不得声称已验证内部 DOM/CSS。
- 动态内容支持自动冻结、忽略区域和分段复核。

### 5.7 问题模型

- 同一元素的多个差异合并为一个问题。
- 问题包含多个子差异：类型、目标值、当前值、差值、置信度和证据区域。
- 问题字段至少包含：严重度、稳定性等级、元素描述、普通话描述、修复建议、证据、来源和状态。
- 点击问题必须在开发图和 DOM 中定位对应元素；无法定位时显示原因。
- 问题支持忽略、恢复、标记已修复和复制建议。

### 5.8 对比模式

1. 开发图标注：在开发截图上绘制编号、边界和问题摘要。
2. 平铺对比：设计图和开发图并排，支持同步缩放和同步滚动。
3. 透明度叠加：对齐后重叠显示，支持透明度调节和闪烁对比。

### 5.9 角色视图

- 设计视图：视觉差异、设计目标、标注证据和优先级。
- 开发视图：DOM/CSS、目标值、当前值和补丁建议。
- QA 视图：验收规则、步骤、证据、未检查项和复验状态。
- 角色切换不改变底层问题数据。

### 5.10 AI 能力

- 核心检测无需 AI API。
- AI 必须由用户主动触发，且调用前展示将发送的数据范围。
- 首批适配 OpenAI、Gemini、Kimi 和 DeepSeek。
- 每个适配器配置供应商、API 地址、模型名和 Key；按模型能力声明文本、图像和结构化输出支持。
- 不具备视觉能力的模型只能接收结构化差异和文字，不得静默降级后仍声称完成图像分析。
- AI 功能包括：低置信度语义对齐、问题解释、组件命名、按钮业务逻辑推测、修复建议和补丁草案。
- “AI 推测业务逻辑”只分析用户选中的按钮或组件。

### 5.11 代码整改

- 工具输出解释、目标值、建议 CSS/DOM 修改和可复制补丁。
- 补丁必须附带来源元素、假设和适用范围。
- MVP 不读取、修改或提交用户的代码仓库。

### 5.12 评分与通过规则

- 默认满分 100 分。
- 严重问题默认扣 8 分，中等问题扣 3 分，轻微问题扣 1 分。
- 同一组件的累计扣分默认上限为 20 分，避免重复子差异无限放大。
- 默认通过条件：总分不低于 95 分，且不存在严重问题。
- 严重度由差异幅度、影响面积、组件业务重要性和是否缺失共同决定。
- 用户可在项目中覆盖容差档位和通过阈值，但每次运行必须固化实际规则快照。

### 5.13 容差预设

MVP 提供严格、标准、宽松三档，并允许项目级覆盖。以下数值是首版校准起点，发布前以基准测试集调整：

| 类型 | 严格 | 标准 | 宽松 |
| --- | ---: | ---: | ---: |
| 位置偏差 | 2px | 4px | 8px |
| 尺寸偏差 | 2px | 4px | 8px |
| 颜色差异 ΔE | 2 | 4 | 8 |
| 字号差异 | 1px | 2px | 3px |
| 圆角差异 | 1px | 2px | 4px |

### 5.14 报告导出

- 标注 PNG：包含问题编号、严重度和可读标注。
- Markdown：包含摘要、评分、问题清单、证据引用和修改建议。
- JSON：包含版本化 Schema、输入信息、规则快照、对齐结果、问题、子差异和导出元数据。
- MVP 不导出 PDF。

### 5.15 主题与个性化

- 内置九套预设主题和一套本地自定义主题。
- 主题编辑器开放页面背景、面板背景、主文字、次文字、边框、强调色、圆角和光效强度。
- 支持 JSON 导入、复制、恢复默认、实时预览和本地自动保存。
- 主题仅影响呈现，不影响截图、检测阈值、评分和导出数据。

## 6. Technical Constraints（技术约束）

1. 前端使用 Vue 3、TypeScript、Vite 和 Ant Design Vue。
2. Chrome 插件与本地工作台共用组件、类型和主题包。
3. 本地服务使用 Node.js；图像与 OCR 引擎使用 Python/OpenCV/PaddleOCR。
4. 元数据和问题数据存储于 SQLite；图片、截图和导出物存储于本地素材目录。
5. 核心分析在离线状态下可运行。
6. Figma 与 AI 访问均为可选外部连接，失败时不得阻断本地核心检测。
7. Figma Token 和 AI Key 存入系统钥匙串，不得以明文写入 SQLite、日志或普通配置文件。
8. AI 发送图片、裁剪区域或页面文字前必须逐次获得用户授权。
9. 本地服务只监听回环地址，不向局域网暴露。
10. MVP 首发 macOS，架构和文件路径抽象需预留 Windows。
11. 插件采用开发者方式安装；本地服务提供 macOS 开发安装包。
12. MVP 首先覆盖桌面 Web；移动端 H5 只做架构预留，不进入首版成功标准。

## 7. Data and Privacy（数据与隐私）

- 默认所有项目、图片、DOM 快照和检测结果只保存在用户本机。
- 外部传输采用逐次授权，不允许通过“已开启 AI”推导永久上传权限。
- 授权界面必须列出供应商、模型、图片数量、裁剪范围和文字数据类型。
- 日志默认脱敏 URL 查询参数、页面文字、文件路径、Token 和 API Key。
- 用户可以删除项目及关联素材；删除前显示影响范围并采用可恢复方式处理。
- JSON/Markdown 导出可能包含页面文字和路径，导出前给出隐私提示。

## 8. Non-goals（明确不做的事）

MVP 不包含：

1. 团队账号、成员权限、在线协作和云端项目同步。
2. 多租户、订阅、计费、额度和运营后台。
3. 移动端 H5、原生 iOS/Android 应用验收。
4. 自动修改、测试、提交或推送用户代码仓库。
5. Figma 整个文件或组件库的双向同步。
6. Chrome Web Store 发布和自动更新。
7. Windows 正式安装包。
8. 跨域 iframe、Canvas、WebGL、视频内部 DOM/CSS 的结构验证。
9. 动画过程、视频帧序列和交互行为的自动回放验收。
10. PDF 报告。
11. 使用 AI 替代确定性的像素测量和评分。

## 9. Success Criteria（成功标准）

### 9.1 基准测试集

- 50 组桌面 Web 页面。
- 至少 500 个由人工标注的真实差异。
- 覆盖官网、后台工作台、表单、列表、弹窗、长页面、固定导航和常见动态区域。

### 9.2 检测质量

- 稳定能力问题精确率不低于 90%。
- 稳定能力问题召回率不低于 85%。
- 位置和尺寸量化误差控制在 ±2px。
- 同一元素多差异合并准确率不低于 90%。
- 实验能力单独统计，不得拉高稳定能力指标。

### 9.3 性能

- 普通视口核心检测在 30 秒内完成。
- 整页截图核心检测在 90 秒内完成。
- 进度 UI 在 1 秒内显示任务已进入队列或开始运行。
- 用户取消后 3 秒内停止可中断任务并清理临时资源。

### 9.4 可靠性

- 20 次连续核心验收运行无崩溃、无数据库损坏和无素材丢失。
- Figma、OCR 或任一 AI 供应商失败时，本地核心检测仍可完成并给出明确降级状态。
- 重新打开应用后项目、页面、批次、规则快照和自定义主题可恢复。
- 当前视口与整页截图均保留可追溯输入元数据。

### 9.5 安全与隐私

- SQLite、配置文件和日志中不存在明文 Token/API Key。
- 未经逐次授权，不向 AI 供应商发送截图、裁剪区域或页面文字。
- 本地服务无法从非回环网卡访问。

## 10. Release Acceptance Checklist（发布验收清单）

- [ ] Chrome 侧栏能采集当前视口和整页截图。
- [ ] 本地图片和指定 Figma Frame 均可作为设计输入。
- [ ] DOM/CSS 增强采集可授权、可关闭、可解释。
- [ ] 几何对齐、人工微调和语义对齐降级路径可用。
- [ ] 稳定检测与实验检测在 UI 和导出中明确区分。
- [ ] 同一元素的多个差异合并为一条问题。
- [ ] 标注、平铺、叠加三种模式可用。
- [ ] 设计、开发、QA 三种视图基于同一问题数据。
- [ ] 评分、严重阻断和项目容差覆盖可复现。
- [ ] AI 供应商可独立配置并经过能力检查。
- [ ] AI 上传前逐次授权可用。
- [ ] Figma Token 和 AI Key 存入系统钥匙串。
- [ ] PNG、Markdown 和 JSON 导出通过 Schema 与视觉检查。
- [ ] 50 组基准测试达到质量与性能指标。
